# Nova — mobile

Personal on-device AI companion for Android. Runs as a background service with
**no app screens** — the only visible surface is a status icon (foreground-service
notification + a floating overlay dot). See [`docs/design.md`](docs/design.md) and
[`docs/architecture.md`](docs/architecture.md) for the full vision.

- Package: `com.tokenburners.nova`
- Flutter stack: GetX + Hive
- Android only (iOS blocks persistent mic + overlays at the platform level)

## Setup (clone & run)

Needs **Flutter 3.x (Dart ≥ 3.13)** and the Android SDK/NDK (Android Studio).

```bash
git clone <repo-url>
cd Nova
flutter pub get
flutter run                       # debug, on a connected device/emulator
# or: flutter build apk --release --target-platform android-arm64
```

Nothing else to fetch:
- The ~40 MB Vosk offline speech model is committed at
  `assets/models/vosk-model-small-en-us-0.15.zip`.
- The ~1.9 GB LLM weight is **not** in the repo — the app downloads it on first
  run (Hugging Face). Until it lands, commands run on the keyword parser.
- `android/local.properties` and the Gradle wrapper are generated by `flutter`
  on first build (they're git-ignored).

Min SDK is **30** (Android 11) — required by the Vosk plugin.

`MainActivity` (channel hub), `WakeWordForegroundService` (mic stream + capture),

driver), `WhisperBridge` / `LlamaBridge` (STT/LLM, JNI stubs),
`WakeWordDetector` (pluggable, `Noop` default), `BootReceiver`, `WavWriter`.

## Worker loop

`Wake Up` → enqueue → drain one at a time:

```
STT → LLM → reasoning_engine → dispatcher → skill → TTS
```

The status icon reflects the whole queue (`working` until it fully drains), not
per task. Irreversible actions (`whatsapp.send`, `gmail.send`, deletes) state a
confirmation prompt and hold — the **next** utterance is read as yes/no rather
than a new command, within a 20 s window.

## Current state

**Voice I/O is real** (no native build): `flutter_tts` drives Android's
TextToSpeech for audio out, `speech_to_text` drives Android's SpeechRecognizer
for the wake phrase **"Nova"** and the command. `WakeWordService` runs the
listen loop from Dart; the foreground service just keeps the process alive and
holds the mic-typed FGS. Recognition pauses while Nova is `working` so it
doesn't transcribe its own speech.

Say **"Nova, <command>"** — or "Nova" then wait for the chime and speak the
command. Working commands: `open <app>` / `launch <app>`, `message <name>
saying <text>` (WhatsApp, allow-list gated), `battery`, `flashlight on/off`,
`volume up/down`, `what's the time` / `date`, `note <something>` / `read my
notes`.

**Live end to end:** wake + STT + TTS, the FIFO queue + worker, reasoning +
spoken yes/no confirmation, the WhatsApp allow-list (checked in the reasoning
engine *and* the skill), the dispatcher, `system.battery`, `app_launcher.open`,
`clock`, notes, the generic Accessibility driver (`app_control` + `whatsapp`),
and screen-off idle → `sleeping` / unlock → `available`.

**Still stubbed** (the fully-offline path — behind clean seams, `TODO(nova)`):

| Piece | Seam | Status |
|---|---|---|
| whisper.cpp STT | `NovaChannels.STT` / `WhisperBridge` JNI | not linked; `speech_to_text` used instead |
| llama.cpp LLM | `NovaChannels.LLM` / `LlamaBridge` JNI | not linked; `LlmService` keyword parser used instead |
| Piper voice | `TtsService` | using system TTS voice |
| Native wake word | `WakeWordDetector` (`NATIVE_CAPTURE=false`) | using `speech_to_text` loop |

`ModelStore` still expects sideloaded model files at `<appSupport>/models/` for
when the JNI layers land; picks 3B primary vs 1B fallback by device RAM.

> **Privacy note:** `speech_to_text` may route audio through Google's recogniser
> depending on the device's offline-recognition support — so the design doc's
> "nothing leaves the phone" only fully holds once whisper + llama.cpp are
> linked. This is the testing bring-up, not the end state.

### Sideload / Play Protect

Nova's permission set (accessibility + query-all-packages + record-audio +
overlay) trips Play Protect and Samsung Auto Blocker, which hard-block install
with no "install anyway". Turn off **Settings → Security and privacy → Auto
Blocker** (Samsung) and/or **Play Store → Play Protect → scan apps**, or
`adb install -r -g app-arm64-v8a-release.apk`.

## Build order

Follows `docs/design.md` §"Suggested Build Order". Done: foreground service +

generic Accessibility driver + WhatsApp allow-list. Next: a real
